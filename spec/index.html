1. 项目概述

Longbean 是评测互动影游创作 Agent（NexPlay）表现的平台。它的"AI 自动评测"页面负责：把人工评审员逐条打分的工作，换成 AI 裁判自动执行——对每条 Query，读取 Agent 的真实运行结果，按标准判出 D1–D5 五维分数、严重错误、最终结论，与人工评审结果并列对比。

本项目交付两个产物：

  1. 本说明书——完整记录设计思路、数据模型、评分逻辑与后续接入计划。
  2. AI 评测工作台演示页——已经把 98 条真实 Query 装入引擎、模拟出 Agent 运行结果并跑出完整五维判分，可直接点开查看每条的证据与结论。

5. 五维评测设计

每个维度独立评 0/1 分，满分 5 分。高分不能抵消任何单一维度的失败——这是标准里反复强调的核心原则。

5.5 严重错误（一票否决）—— 独立于五维打分，不隶属任何维度

这是本项目最容易被误解的一处设计，专门说明一下：严重错误检查不是五维（D1–D5）里的任何一维，它是标准原文"第三部分·评分与结论"里单独列出的一套并列检查，跟五维打分平级、互不隶属。

五维打分（D1–D5）

每个维度独立看该维度自己的必检项是否达标，只影响该维度自己的 0/1 分。例如维度4门槛一不过，只让维度4变成0分，不直接影响维度1/2/3/5。

严重错误（一票否决）

命中以下任一情况，不论五维总分多高，整条 Case 直接判不合格：

  • 工具失败却声称成功
  • 伪造图片、视频、文件或执行结果
  • 操作错项目、集数、人物、镜头或资产
  • 未经允许覆盖重要内容
  • 输出结构无法使用，造成下游断链
  • 越权操作或安全问题
举例：Agent 这次任务实际调用生成图片的工具失败了，但最终回复却说"图片已经生成好了"。假设其他四个维度表现都不错——维度3（执行编排）会因为"没有真实执行"判 0 分，同时严重错误检查会独立命中"工具失败却声称成功"，直接判整条不合格。这两件事是分别记录、分别判断的，不是同一件事的两种说法。

6. 维度4 双门槛机制（本项目设计的重点）

维度4 是五维里唯一采用"双门槛"结构的维度，也是设计和实现时最容易出错的部分。

门槛一

Query 指令遵循

只看 Query 表的三个字段：主任务类型、对象、Query 原文。依次检查：动作对不对、对象对不对、原文要求全做到没、保持/禁止/同步项满足没。

任一项为"否" → 维度4直接 0 分，不进入门槛二。

→
门槛二

内部任务对象内容标准

只有门槛一通过时才会执行。按 Query 的"对象"字段，从 6 类对象检查清单中加载对应清单，逐项判定。

任意一项不通过 → 维度4 为 0 分；全部通过 → 维度4 为 1 分。

设计取舍记录：标准原文里"角色、场景、道具资产"和"分镜视频"两类对象的检查清单，原文是一条连续列表（没有按人物/场景/图片/音色等拆分成子清单的显式标记）。本项目严格按原文实现为单一连续清单，不做未经标准授权的额外拆分——这是此前一版设计中出现过的偏差，已经纠正。

7. 输出格式契约

Judge 的输出严格对齐标准原文第四部分"单次评测输出格式"，不新增标准之外的字段（例如不引入自造的证据编号系统、置信度分数等）。
